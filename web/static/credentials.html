S3 credentials

A credential is a SigV4 keypair for the S3-compatible gateway: one access key ID, one secret, and the exact S3 actions it may sign. Telegram remains the only payload backend; the keypair only decides what this client is allowed to ask the gateway to do. Secrets are encrypted at rest and never leave the server except when you explicitly reveal one.

Revoke this credential?

Every request signed with this access key is rejected from the next request onwards — there is no grace period. This cannot be undone: a revoked credential cannot be reactivated or reveal its secret. Issue a replacement first if the client must keep working.

Rotate this credential?

One step issues a new keypair with the same scopes and immediately revokes the old access key. Any client still signing with starts failing right away, so update it with the new secret during this change window. The new secret is shown once.

Reveal the secret access key?

The secret is decrypted server-side and this action is audit-logged. It will be displayed in this browser tab and is never stored by the page. Anyone who can see this screen can read it — close the panel when you are done.
