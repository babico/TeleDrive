# TeleDrive — S3 fidelity, recovery and security execution plan (2026-11-02)

**Status:** Planned, not implemented. **Baseline:** main at `ddedb6519fd47991c3b94093c27087ee8fb55b39` (re-check HEAD before editing). **Owner intent:** Implement real behavior, not cosmetically successful API responses. Preserve one-container Web/REST/S3, one SQL catalog and Telethon USER MTProto. **Do not** change S3 manifest status until code, tests and live client evidence agree.

## Contract decisions

1. **Physical GC remains an owner-operated toggle.** Preserve the existing admin authorization, typed confirmation, dry-run, retention/reference/retry fences and audit. **Do not introduce compulsory signed acceptance bundles, two-person approvals, or external gate prerequisites** for the owner to enable GC. Document that physical deletion is irreversible and that the owner bears the backup decision.
2. **Bootstrap password change will be server-enforced.** Keep the one-time `admin/admin` bootstrap (do not overwrite an existing admin). Until that account's password is changed, authorize only login, self-password-change, logout, current-user identity, health and required static assets. Deny protected REST/S3/admin/WebSocket flows without handing out keys. Admin must be able to complete a change without a bootstrap deadlock. Invalidate old sessions, audit password change, test concurrency and existing admin installations.
3. **Original-media recovery and independent payload backup are owner-run tests.** Supply scripts, instructions, expected evidence, fail-closed handling and cleanup steps, but never perform them on the owner's production media from CI or a developer machine. No fabricated original IDs, independent hosts, 429s or restore receipts.
4. A supported S3 operation means a **tested documented TeleDrive contract**, not complete AWS behavior. Maintain a separate parameter/variant compatibility matrix. Existing `114 supported / 0 partial / 2 unsupported` is an operation count, not a parity percentage.
5. No fake AWS zone locality, Glacier pricing/latency, IAM principal identity, AWS KMS service or public permissions. Emulated functionality must be labeled and must transfer real bytes when claiming a data move.

## Reality check against current code

| Feature | Actual baseline | Required work |
| --- | --- | --- |
| `GetObject?partNumber=N` | `dispatch.py` returns 501. `MultipartStore.object_parts_for_version` already returns immutable (part number, size, digest, ETag) snapshots, including copied and legacy completed MPUs. | Map requested logical part to verified byte offsets; stream precisely that range with proper AWS response semantics. |
| Directory buckets / CreateSession | `directory_buckets.py` has a deliberate empty list and explicit rejection; no directory-bucket type or session credentials exist. | Implement actual bucket type, directory semantics, short-lived scoped token issuing and verification, or keep endpoints explicitly unsupported. |
| RestoreObject | Real SQL restore access window (`restore_until_ns`), `202`, archive GET gate and `x-amz-restore`; tiering currently changes only metadata, **no bytes move**. | Introduce a real cold payload backend and durable archive/restore jobs, verify bytes/hashes, stage and expire restored copies. |
| Versioning | `Enabled` and `Suspended` paths exist; history is immutable, but AWS `null` version and MFADelete edge semantics are not complete. | Differential-test and implement null versions, delete markers, cross-surface version deletes and owner-set MFA policy if justified. |
| Object Lock | GOVERNANCE/COMPLIANCE retention and legal holds exist. | Cross-surface invariant tests; governance bypass permissions, default retention races, legal holds, physical GC and restore. Caveat: app WORM cannot prevent an owner deleting Telegram media outside TeleDrive. |
| Lifecycle | Abort-incomplete MPU and expiration-to-logical-delete exist. | Version-aware noncurrent expiration, transitions and durable status; never auto-delete Telegram media when GC is off. |
| ACL/Policy | Access-key CanonicalUser grants, private-only, limited condition grammar; owner controls exist. | Precise scope/ACL/policy intersection, condition expansion, optional explicit public mode design, cross-account model only if real principals are built. |
