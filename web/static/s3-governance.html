S3 governance

Every control below exists on the S3 API and is signed server-side with a real S3 credential. The browser never receives a secret key.

No buckets exist yet. Create one under S3 → Buckets.

Leave the credential selection alone to let the server pick the first active key that grants each action.

No active S3 credentials. Create one under S3 → Credentials; governance writes need a key with the matching s3:* permission.

The raw S3 code and message are shown verbatim so a Deny can be debugged, never a generic "something went wrong".

Bucket policy

IAM-style JSON document evaluated by the gateway. GET ?policy / PUT ?policy / DELETE ?policy.

Deny always wins over any Allow, and every Principal.CanonicalUser must be an existing, active access key from S3 → Credentials. A policy is never a substitute for IAM (there is no IAM here).
Validation errors from the S3 engine appear above with their raw AWS code.

Ownership controls

Controls whether object ACL grants participate in authorization.

Switching to a model that honours object ACLs does not create any grants by itself.

Public access block

Four forward-looking guards stored per bucket. AWS default: all four ON.

Turning any flag off is a deliberate owner decision. TeleDrive has no anonymous object path, so this does not publish anything by itself — it only relaxes the stored guard and is recorded in the audit log.

Object lock

Bucket-level default retention applied to new objects.

Enabling Object Lock is one-way. It cannot be disabled, and COMPLIANCE retention cannot be shortened or removed — not even by an admin. There is no delete API for this configuration.

Notifications

Object mutations enqueue outbox rows and a retry worker POSTs them to an owner-approved HTTP(S) webhook.

SQS, SNS and Lambda are not supported. AWS queue/topic payloads cannot honestly exist over a private Telegram gateway, so those XML elements fail closed with 501. This is a real webhook fan-out, not an AWS queue integration.

Approved destinations:

No allowlist is configured (storage.notification_destinations); every webhook destination will be rejected until the owner adds one.

Saving with "Deliver events" off sends an empty NotificationConfiguration.

Replication

AWS-shaped rules over the existing TeleDrive cross-account replica engine.

A rule's destination is a configured Telegram credential-set label, not an AWS bucket or ARN. The engine already keeps a second Telegram copy of every chunk in that account and repairs missing copies. One replica per chunk means enabled prefixes must be disjoint; overlap is rejected with InvalidRequest. A stored configuration is authoritative: no enabled match means no replica (the operator-wide default does not apply).

No Telegram account labels are configured. Add/authorize an account under Settings → Telegram; the replica engine needs a second account to copy to.

Intelligent-Tiering

A real access gate in the SQL catalog, evaluated by the tiering scheduler.

This is not Glacier. No Telegram bytes move, are copied, compressed or deleted. An archived object answers 403 InvalidObjectState until a RestoreObject opens a bounded read window; the chunks stay on Telegram for the whole lifecycle.

Storage reports

Analytics, inventory and metrics configuration CRUD (Phase N). A background runner writes real report objects.

Documented deviations from AWS: the inventory CSV is gzip and its ETag is the stored object's SHA-256; analytics is JSON Lines (not Parquet); metrics is computed locally and written under reports/metrics/<id>/ — it is not delivered to CloudWatch. Schedules are Daily or Weekly only.
