# TeleDrive v1.0.11 — the audit release

> **One sentence:** four auditors read every one of the 54 documentation
> pages and checked roughly 3,600 claims against the code; nine real
> defects surfaced, every one is fixed, and the docs now say what the
> software does.

## Why this release exists

Documentation drifts silently. This release is the result of auditing the
whole tree the other way round: instead of testing code against a spec, it
read every documented claim — every number, path, endpoint, config key,
default and behavioural sentence — and checked it against the source.

The audit found **nine defects the test suite could not see**, because each
one was a documented contract the code did not honour:

- **IPv6 was unusable.** The trusted-host middleware split the `Host`
  header on the first colon, so `[::1]` became `"["` and the documented
  default allowlist entry could never match. Every IPv6 request answered
  400 while localhost worked.
- **`rest_max_upload_bytes: 0` could not be configured**, although three
  guides describe 0 as "uploads disabled by policy". The setting rejected
  it; the documented switch was unreachable.
- **The master-key environment fallback never worked in the web service.**
  `settings_runtime` always exports the file path (with the `/config`
  default), and the loader treated any non-empty path as file mode — so
  `TELEDRIVE_S3_MASTER_KEY` was ignored in exactly the deployment shape the
  encryption guide describes.
- **`HEAD` on a public website answered 405.** The handler had a HEAD
  branch; the routes were GET-only and FastAPI does not add HEAD.
- **`CreateSession` accepted an unsigned mode header.** A client could add
  `x-amz-create-session-mode: ReadOnly` after signing and the server
  honoured it — a value outside the signature.
- **A ranged `CopyObject` bypassed the per-bucket quota** — the one way to
  write past a quota — because only PUT, POST-form and MPU completion
  called the quota guard.
- **Two `AES256` default-encryption rules were accepted**; AWS permits
  exactly one.
- **Client-side ciphertext could be indexed.** A `TDENC1`-prefixed `.txt`
  was extracted as replacement-character text and entered the search index.
- **Six configuration stores turned a cascading foreign-key violation into
  a 500** (and the pin store into a silent success) when a bucket was
  deleted between the existence check and the commit.

## The bigger changes

### Bucket deletion is atomic (schema 31)

Every bucket-name-keyed configuration table now carries a real
`ON DELETE CASCADE` foreign key, so deleting the bucket row removes its
configuration in the same statement. The old explicit sweep had a window:
a configuration write whose existence check ran in an earlier transaction
could commit an orphan row afterwards. SQLite rebuilds those tables
(it cannot alter a foreign key), PostgreSQL and MySQL replace the
constraint; the step is idempotent and preserves every row and index.
SQLite foreign-key enforcement is now on, which is itself a behavioural
change — programmatic fixtures that synthesised orphan rows must disable it
while doing so.

### Full lifecycle filtering

`Filter`/`And` now accepts `ObjectSizeGreaterThan` and `ObjectSizeLessThan`
with AWS's exclusive bounds and the 0–5 TiB range, alongside prefix and
tags, and the evaluator applies them to expiration and transition
candidates (a missing size fails closed).

### Cyberduck is a tested client

The real `duck` CLI (9.6.0) runs a live round trip in CI: list, create,
folder, upload, long list, download with a hash check, delete. Multipart
uploads now complete — the gateway exempts the zero-length
`?uploads=` initiation from the unsigned-upload rule (declared
`Content-Length: 0` only, never a chunked body), which was the one shape
that blocked every upload above Cyberduck's multipart threshold.

### Signature canonicalization and dispatch details

The SigV4 canonical query accepts both the wire-bytes form botocore signs
and the spec-literal re-encoded form, so an unencoded `/` inside a
`response-*` value authenticates. `s3:BypassGovernanceRetention` is a real
scope wired to the retention route. `bucket-owner-read` is honoured.

## Upgrading

Schema 30 → 31 runs at startup under the existing lock. The FK rebuild is
idempotent; a crash mid-step rolls back on SQLite and is repaired on the
next start on PostgreSQL/MySQL.

Operator-visible consequences:

- A configuration write that races a bucket delete now fails with
  `NoSuchBucket` (404) instead of creating an orphan row.
- SQLite enforces foreign keys; any external script that inserts rows for a
  bucket that does not exist will be refused.
- Documentation numbers changed (schema 31, 166 routes, 91 scopes,
  142/99/44 role counts) — if you script against any of them, re-read the
  reference pages.
