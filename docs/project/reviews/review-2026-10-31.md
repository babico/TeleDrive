# Full-codebase review — 2026-10-31

A whole-tree review by six independent read-only reviewers (storage core, S3
data plane, web/API layer, persistence core, S3/storage test realism,
web/meta/e2e test realism). Every claim was re-verified by the coordinator
before a fix was attempted; the reviewers' false positives were dropped.

This page is the ledger. It exists so that "we reviewed everything" is
auditable rather than a claim: what was fixed, what was declined on purpose,
and what remains someone else's job.

## 2. Declined on purpose

These are not oversights; each is a documented trade-off or an honest
refusal. A future reviewer will meet them again, and should not "fix" them
without a decision.

- **`GET ?partNumber=N` answers 501.** The storage model has no retained
  part boundaries after completion; fabricating ranges would be worse than
  refusing. Documented in `docs/S3_SPECS.md` (GetObject row).
- **`SelectObjectContent` accepts `RequestProgress` and emits no Progress
  events.** Parsed for schema compatibility, documented in the module; the
  Records/Stats/End stream is the contract that matters.
- **`must_change_password` only nudges the UI.** The first-boot `admin`/
  `admin` account is a documented, deliberate bootstrap; a server-side
  forcing function would break automation on a fresh install. `UPGRADING §7`
  tells operators to change it immediately.
- **Share tokens are stored in plaintext.** They are anonymous-download
  capability URLs the admin must be able to re-display; the alternative is
  a one-time reveal that breaks the UI. Session and API-key tokens stay
  hashed.
- **An API key can reach admin-only routes with the exact scope it was
  minted for.** That is the delegation model: the role gate governs humans;
  the key *is* the grant, capped by the minting admin's own permissions.
  Recorded in `docs/API_REVIEW.md` as "by design".
- **The audit middleware opens a DB read per request** to attribute the
  user. Correctness over micro-optimisation; the trusted-host middleware now
  runs first, so rejected requests no longer pay it.
- **Raw SQL in `teledrive/`** (quota, dedup lookup, GC metrics) bypasses the
  table declarations. All of it is portable and annotated; the web layer's
  four remaining statements are read-only aggregates (the reindex candidate
  query moved to `teledrive/storage/content_index.py`, where it also picked
  up the full extraction extension set instead of a hardcoded ten). This is a consistency
  note, not a defect.
- **The 2 permanently unsupported operations** (`GetObjectTorrent`,
  `WriteGetObjectResponse`) have no seeder and no Lambda runtime.
- **Physical GC remains owner-gated.** `deletion_permitted` stays `False`
  until an independent backup host, an authorised soak and a restore drill
  exist. No commit can close that.

## 3. Test-realism items left as-is

- Source-text assertions in `test_credentials_ui.py`,
  `test_page_composition.py` and `test_s3_governance_ui.py` pin real safety
  properties but are structurally brittle. They are honest about being
  structural and have caught real drift; rewriting them to behavioural tests
  is a larger project with no current bug behind it.
- `test_s3_gateway.py`'s `_page` test re-implements the catalog's ordering
  contract in its fake. It still exercises the grouping logic; a drift in
  the real contract would be caught by the HTTP-level pagination tests.
- The unsigned-auth matrix sends empty bodies ("no mutation" is asserted
  through the transport counter and the catalog, not the body).
- The SSE-C corrupt-ciphertext test accepts either an exception or a 5xx; it
  asserts the property that matters (no plaintext leak).
- The retry/restart matrices still run on SQLite. The two things SQLite
  cannot prove (schema-init races, portable SQL semantics) now run on real
  PostgreSQL and MySQL in CI; porting the full race matrices is worthwhile
  but large.
- The suite has no shared `conftest.py`; four fixtures re-implement the
  tmp-app setup with small drift. Consolidating is safe work, not urgent.
- Two tests patch `pathlib.Path.mkdir` globally because the app hardcodes
  `/data` and `/uploads`. The patch is test-scoped and xdist runs one file
  per worker, but it is a smell worth removing by making those roots
  configurable.
