# TeleDrive v1.0.10 — the fidelity release

> **One sentence:** the S3 fidelity program landed: real directory buckets
> with session credentials, a physical cold archive with a truthful
> RestoreObject, AWS-exact versioning and lock semantics, a server-enforced
> first-boot password rotation, and a per-operation evidence matrix that
> keeps every claim measurable.

## Why this release exists

After the 1.0.9 review release closed every verified defect, the remaining
gap to honest S3 compatibility was protocol fidelity: operations that
existed but answered with refusals, semantics that were close-but-not-AWS,
and evidence that was global rather than per-operation. This release is the
execution of the S3 fidelity plan (handoffs 06–10) plus the evidence
program that proves it.

## The headline changes

### S3 Express directory buckets are real (handoff 07)

`bucket_type` general|directory with typed create/list/delete and immutable
`base--zone-id--x-s3` names, where the zone id is a configured **logical
compatibility label** — never a claim of AWS Availability Zone, One Zone
durability or Express throughput. `ListDirectoryBuckets` enumerates real
rows with HMAC'd scoped continuation tokens and never leaks general
buckets. `CreateSession` issues short-lived cryptographically random
credentials bound to one bucket and one mode: the session token is stored
only as a SHA-256 hash, the secret Fernet-encrypted with the server master
key, revocation is a durable SQL flag visible to every worker, and zonal
requests must carry the `s3express` signing scope plus the signed
`x-amz-s3session-token` header. Schema steps 28–29.

### A physical cold archive and a truthful RestoreObject (handoff 08)

`ColdBlobStore` seals the stored representation (ciphertext for SSE-C and
envelope — no client key needed) with temp-file + fsync + hash-verified
readback and a manifest that carries chunk lineage and digests but never
key material. A resumable state machine (`HOT → ARCHIVING → ARCHIVED →
RESTORING → RESTORED_TEMP → ARCHIVED`) with idempotency keys, durable
worker leases and generation fences drives `RestoreObject`: 202 on
acceptance, `x-amz-restore: ongoing-request="true"` while the copy runs,
and GET opens the window only after whole-SHA256 verification in the same
transaction. A corrupt or missing archive settles back with the error
recorded — never a permanently unreadable object. Tier transitions never
delete Telegram messages; the GC collector additionally permits hot
deletion only when the cold blob readbacks with the exact whole SHA-256 at
collection time. Lifecycle gains `Transition`,
`NoncurrentVersionTransitions` (with `NewerNoncurrentVersions`),
`NoncurrentVersionExpiration` and `ExpiredObjectDeleteMarker`. Schema
step 30.

### AWS-exact versioning, ACL, policy and lock semantics (handoff 09)

- **Suspended-bucket null-version slot**: every suspended write occupies
  the null-version slot and retires the previous null occupant; enabled-era
  versions are immutable history; a suspended DELETE inserts a marker
  carrying the null version ID — the verified AWS contract, uniform across
  PUT, copy, multipart, REST and the S3 gateway (previously a suspended
  write destroyed enabled-era heads and a suspended DELETE removed the
  head with no marker).
- **ACL**: the canned set is exactly AWS's eight (unknown values are 400,
  not 501); `PUT ?acl` accepts the header/canned alternative with the
  grammar tightened (blank or grantee-less headers are 400).
- **Bucket policy**: condition operators expand to the common AWS set —
  string (multi-value), CIDR `IpAddress`/`NotIpAddress` (IPv4/IPv6),
  `Bool`, `Numeric*`, and `Date*` with temporal comparison — with AWS's
  missing-key semantics, write-time validation, deny precedence, and a
  corrupt stored policy answering `400 MalformedPolicy` instead of falling
  back to no policy.
- **Object Lock**: a 16-path fence audit (S3 deletes, batch delete, REST
  unlink, WebUI delete, suspended overwrites, copy, rename, GC) — COMPLIANCE
  is extend-only for everyone including the owner; shortening or clearing
  GOVERNANCE retention needs the dedicated `s3:BypassGovernanceRetention`
  scope plus the explicit header, so without both it stays fail-closed.

### GetObject `?partNumber=N` (handoff 06)

Serves the logical multipart part from the immutable completion layout:
sparse-safe offset math (prior part sizes in stored order, never
part-number arithmetic), 206 + `Content-Range` + `x-amz-mp-parts-count`,
single-PUT part 1 as the whole object, an empty 200 for zero-byte parts,
`416 InvalidPartNumber` with `PartNumberRequested`/`ActualPartCount` for
absent parts, and `400` for `Range`+`partNumber`. Every decision matched
against researched AWS/MinIO/RGW behavior. SSE-C multipart layouts are now
verifiable too (the ciphertext ETag shapes are accepted for encrypted
completions), so part reads, `GetObjectAttributes(ObjectParts)` and copies
of SSE-C MPU objects work where they previously failed closed with 409.

### The first-boot admin password is enforced server-side (handoff 06)

While the seeded `admin` account still uses the shipped default, every
authenticated operation is refused — web, REST, S3 (including credential
issue and presign), API keys and the admin WebSocket — through two gates
that sit before authorization. The allowlist is exactly the rotation flow:
login, me, logout, the new self-service `POST /api/v1/auth/password`,
health, the login page, static and certificates. The probe is PBKDF2
against the stored hash, cached keyed by the hash itself (a change
invalidates by construction) and fails closed. API keys and S3 credentials
issued under the default password are denied until rotation: on a
legitimate first boot none can exist.

### The evidence program

- **A per-operation evidence matrix** (`docs/reference/s3-evidence.md`):
  114 supported operations × 7 evidence columns, each applicable cell naming its
  proving test, with a meta test that fails the build when a new operation
  arrives without its row.
- **A parameter-level compatibility ledger**
  (`docs/reference/s3-parameters.md`): 100+ parameter rows with
  SUPPORTED/REJECTED/UNVERIFIED states, source-derived and enforced.
- **A fourth independent client** in the live matrix: minio-py 7.2.20
  (its own SigV4 signer, botocore-free). Cyberduck is documented as
  explicitly untested — never an implied "works".
- **The race and restart matrices run on real PostgreSQL 17 and MySQL 8.4**
  inside the CI database job, and the GC lease claim survives InnoDB
  deadlock elections.
- **A DR rehearsal you can actually run**: the documented owner command
  works verbatim, verifies full bytes plus first/middle/cross-boundary/last
  ranges, unwraps envelope keys, cross-checks independent attestations and
  writes a redacted evidence record — with an offline self-test.

## Operator-visible consequences

- **First boot after upgrading**: the login page forces the admin password
  rotation before anything else works. See
  `docs/start/first-upload.md`.
- **Suspended-versioning buckets**: the AWS-correct null-slot semantics
  replace the previous destroy-the-head behavior. A suspended write now
  preserves enabled-era versions; listings may show one additional old
  null-version row written before this release.
- **SSE-C UpdateObjectEncryption**: the old-key family is parsed under the
  AWS-spelled names (`x-amz-copy-source-server-side-encryption-customer-*`).
  The earlier double-prefixed spelling was never an AWS name; clients
  sending it must switch to the correct one.
- **Schema 27 → 30** (append-only, idempotent; runs at startup).
- The test suite grew from 2085 to 2616 passing tests.
