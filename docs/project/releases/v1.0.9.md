# TeleDrive v1.0.9 — the review release

> **One sentence:** a whole-tree review found 55 verified defects; every one
> of them is fixed in this release, with a regression test beside each fix.

## Why this release exists

After the 1.0.8 candidate, the codebase was reviewed end to end by six
independent readers (storage core, S3 data plane, web/API layer, persistence
core, and two test-realism reviews). Every claim was re-verified before a
fix was attempted. Of the findings, the ones that would have shipped:

- **Three unbound names produced bare 500s** — `EnvelopeError` was never
  imported (a corrupt SSE-S3 marker answered 500 instead of an XML error),
  the CORS middleware referenced `matched` only inside a branch, and a store
  rewiring left `_text` behind in a Telegram handler that the dashboard
  calls on every load.
- **The admin log websocket had authentication but no authorization.** Any
  viewer could stream admin-only log lines (credential ids, presigned URLs).
  It now closes 4403, and the route surface freeze finally covers websocket
  routes.
- **CopyObject permanently broke envelope-encrypted objects:** the copy
  answered 200 and every later GET answered 400, with no recovery.
- **A reindex filter returned nothing on MySQL** — `||` is logical OR there,
  not concatenation, so the predicate silently matched almost nothing. No
  error, no log. It also only recognised ten of the thirty-five extractable
  extensions.
- **A concurrent login could deadlock on InnoDB** (gap locks around the
  upsert) and, without the new unique indexes, produce duplicate identity
  rows that broke the Prometheus scrape.
- **Default object-lock was applied after the publish commit** — a crash in
  that window left a COMPLIANCE-retention version deletable.
- **The GC re-verify fence swallowed every error**; a racing collector could
  delete media a new head still referenced; the dedup path could commit an
  alias whose base had just been collected.
- **Report generation was accepted by the API and never run**; session
  purging, share cleanup on bucket delete and the strategy setters were
  written and never wired; the strategy change itself was silently reverted
  on any deployment with a master key.
- **Login throttling keyed on the proxy address** — one client could lock
  every user behind a reverse proxy out of the admin account.
- S3 semantics: `If-Range`, `max-keys=0`, `Allow: DELETE` on the delete-marker
  405, `MalformedXML` for an empty complete, checksums for SSE-S3, the six
  `response-*` overrides (including boto3 presigned URLs), CRC32/CRC32C
  verification on object-control bodies, and an AWS-parity fix for
  unparseable `Range` headers.
- The WebUI delete path now obeys the same WORM/versioning rules as REST,
  the public share stream applies the same read gate, and public website
  reads count as object access so tiering cannot demote a live page.

## Operational changes

- **Schema 27** dedupes existing `telegram_sessions` / `telegram_channels`
  rows (newest `updated_at`, lowest id wins) and adds unique indexes. The
  migration is portable and idempotent; it runs on startup.
- Upload settings nothing read are gone (`retry_*`, `sleep_*`,
  `max_files_per_*`, `caption_template`, `send_mode`, session/api keys in the
  uploader config) — see the upgrade guide §7.9.
- Two-person GC approval is not required; the gates are backup, soak,
  restore rehearsal and the evidence bundle. Physical deletion stays
  **disabled** (`deletion_permitted` is `False`).
- The license is now the **WTFPL**.
- The manual is a published documentation site:
  **<https://babico.github.io/TeleDrive/>**

## Upgrading

Read [the upgrade guide](https://babico.github.io/TeleDrive/operate/upgrade/)
before pulling. The short version: back up the database, the config and the
master key; pull; `docker compose up -d --build`; the schema migration runs
on startup. If your only credential was the first-boot `admin`/`admin`, the
recovery command is in the same guide.
